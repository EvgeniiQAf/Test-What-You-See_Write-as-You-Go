# План рефакторингу та розширення

Цей документ окреслює план рефакторингу проєкту `testmo-ai-helper` для покращення його структури, підтримки та розширюваності.

## Робочий процес

Для кожного основного завдання будемо дотримуватися наступного процесу:
1. Створити нову гілку від `main`.
2. Реалізувати зміни у цій гілці.
3. Ретельно протестувати зміни.
4. Злити гілку в `main` після підтвердження працездатності.

## Глобальні цілі

1.  **Декомпозиція коду:** Провести рефакторинг кодової бази згідно з найкращими практиками, покращити читабельність та розділити великі компоненти на менші модулі з єдиною відповідальністю.
2.  **Абстракція для LLM:** Створити гнучкий шар інтеграції для Великих Мовних Моделей (LLM), що дозволить легко перемикатися між різними провайдерами (OpenAI, Gemini тощо).
3.  **Абстракція для сховища тестів:** Реалізувати шар абстракції для систем управління тестами (наприклад, Testmo), що дозволить легко змінювати сервіс. Це також має включати гнучку систему шаблонів для створення тест-кейсів.

## План дій (6 блоків)

### Блок 1: Базовий рефакторинг
- [ ] Аналіз поточного коду в контролерах та сервісах.
- [ ] Винесення логіки валідації в окремі мідлвери (`middlewares`).
- [ ] Розділення великих функцій на менші, пере використання коду.

### Блок 2: Абстракція сервісу OpenAI
- [ ] Створити загальний інтерфейс для мовних моделей.
- [ ] Оновити `openai.service.ts`, щоб він реалізовував цей інтерфейс.
- [ ] Замінити прямі виклики OpenAI на виклики через абстрактний сервіс.

### Блок 3: Інтеграція з іншими LLM
- [ ] Додати конфігурацію для нової LLM (наприклад, Gemini).
- [ ] Створити новий сервіс для другої LLM, що реалізує загальний інтерфейс.
- [ ] Додати можливість вибору LLM через конфігурацію або параметри запиту.

### Блок 4: Абстракція сервісу Testmo
- [ ] Створити загальний інтерфейс для систем управління тестами.
- [ ] Оновити `testmo.service.ts`, щоб він реалізовував цей інтерфейс.
- [ ] Замінити прямі виклики Testmo на виклики через абстрактний сервіс.

### Блок 5: Гнучкі шаблони для тест-кейсів
- [ ] Винести логіку формування промптів з `testcase.prompt.ts` в більш гнучку систему.
- [ ] Створити механізм вибору шаблону промпту (наприклад, за назвою).
- [ ] Дозволити легке додавання нових шаблонів без зміни коду.

### Блок 6: Інтеграція з іншою системою зберігання тестів
- [ ] Створити сервіс-заглушку для іншої системи (наприклад, запис у локальний JSON файл).
- [ ] Додати можливість вибору системи зберігання через конфігурацію.
- [ ] Перевірити, що перемикання між Testmo та іншою системою працює коректно.
